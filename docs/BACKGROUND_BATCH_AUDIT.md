# 后台批处理异常隔离排查（2026-10-07）

排查依据为 `a78d2d6acd1888b30fcc63ae556afff778373d6d`：单台服务器的队列读取或入队
异常会中止插件更新整轮扫描，排在它之后的服务器持续漏检。
本轮沿相同因果链检查后台巡检、启动恢复、独立成员的批量遥测和运行时收尾。

| 路径 | 确认的问题 | 修复 |
| --- | --- | --- |
| CS2 自动更新 | SSH 跳过判断、时间间隔判断在单台更新的异常处理之外 | 每台服务器的资格判断和更新调用共同隔离；异常记录服务器 ID，后续服务器继续 |
| A2S 后台与显式批量刷新 | 跳过判断或限流/探测异常会触发批次失败，取消其他服务器 | 判断与探测分别有单项边界，保留共享限流、扫描期限和取消传播 |
| steam.inf 定时刷新 | 跳过判断在单项异常处理之外 | 将判断纳入单台刷新边界，失败仍计入聚合统计 |
| 磁盘与主机信息批量读取 | 意外异常或资源收尾异常会取消其他独立探测 | 单项退回既有失败结果，保持输入顺序和其他成功结果 |
| SSH 健康巡检 | 子任务取消通过裸 gather 传播，兄弟任务可能继续占用资源 | 使用 collect_ordered，传播前取消并等待所有兄弟任务 |
| Discord 多账户巡检/关闭 | 一个账户异常会阻断后续账户，启动巡检失败还会阻止定时循环创建 | 逐账户记录并继续；正常巡检下一轮重试失败账户 |
| Discord Gateway 收尾 | client.close 失败会跳过 Gateway task 取消和租约释放 | finally 中等待任务退出并释放租约 |
| 定时任务启动重算 | 一次 SQL/commit 失败会污染共享事务，其他任务更新无法提交 | 先结束读取事务，每条有效任务用独立短事务提交；无更新时不提交 |
| collect_ordered 创建阶段 | 迭代器中途失败时，已创建任务在异常清理范围之外 | 把任务创建纳入同一异常边界，失败时取消并等待已创建任务 |

所有新增的业务异常边界仅捕获 `Exception`，不会吞掉 `asyncio.CancelledError`。
collect_ordered 保留对取消及其他 BaseException 的清理后重抛语义。
不变更每服务器 FIFO、插件更新重试时间、SSH/A2S 并发上限或后台跳过规则。

`tests/test_background_batch_isolation.py` 的 29 个测试场景覆盖持续故障两轮、恢复重试、判断与探测阶段异常、
后续成员执行、有序部分结果、读事务结束、独立写事务、取消传播、兄弟任务退出、
并发槽位释放和 Gateway 收尾。复用插件更新调度、遥测、定时任务和 Discord 既有测试。

排查还检查了插件采集/描述同步 worker、AI/审计保留清理、服务器监控、SSH 连接池维护和
队列记录持久化。已有逐项异常隔离或重试的路径保持原实现；单个安装计划的依赖链、
单事务内需要共同成功的状态/审计写入不适用“单项失败后继续成功”的处理方式。
本报告仅依据仓库代码与隔离验证，不包含线上日志、服务器 SSH、线上数据库或服务重启，
也不代表能证明所有未知运行时故障均已消除。
