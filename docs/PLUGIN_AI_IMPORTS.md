# 插件中心 AI 智能导入

管理员可在 `/plugins` 点击「AI 智能导入」，把 GitHub 上仍在维护的
CounterStrikeSharp、SwiftlyS2 插件加入市场目录。任务只维护插件目录、安装规则和
依赖关系，不会连接游戏服务器，也不会自动执行安装。

## 使用方法

1. 在 `/settings` 保存全局 GitHub Token，再点击「验证已保存的全局 GitHub Token」。
   验证访问 GitHub 身份与额度接口，显示账号、验证时间及 Core/Search 额度和恢复时间。
   替换或清除 Token 会使旧验证失效。发现任务始终使用这个全局 Token，不使用个人 Token
   或匿名请求；任务实际执行前还会重新在线验证。
2. 配置并测试当前管理员使用的 AI provider。导入弹窗显示实际模型，沿用面板现有个人／全局
   AI 配置选择规则。
3. 选择框架、关键词、最低 Star/Fork、排序、最近更新天数、运行时间和目标插件数。
   默认搜索两套框架，按 Star 降序，至少 10 Star、0 Fork，最近 365 天更新，运行 15 分钟，
   最多新增 20 个目标插件。最长 120 分钟、最多 100 个目标插件。
   可以补充公开 GitHub 仓库 URL；补充仓库和依赖不受热门门槛限制。
4. 阅读并勾选 AI 结果核对提示，提交任务。接口立即返回 202，弹窗关闭并打开活动托盘。
   关闭页面不影响任务。托盘显示阶段、当前仓库、耗时、逐项结果和取消入口。
5. 在插件详情核对分类、安装包选择规则、解压来源目录、目标目录、依赖和人工准备项。
   文档依据记录文件路径及 commit。管理员可修改安装规则并标记「已核对」。
   分类、框架和依赖可使用现有插件编辑功能修改。

**分析结果取决于大模型能力，分类、安装配置和依赖可能不准确，请仔细核对。**

## 执行与安装边界

- 所有目录导入任务进入独立全局 FIFO，同一时间执行一个，最多等待 10 个。
  PostgreSQL 保存任务、结果和事件；Redis 租约约束执行者，后台生命周期由 task registry 管理。
- GitHub 请求串行，普通请求至少间隔 2 秒、搜索请求至少间隔 6 秒。搜索排除归档及 fork 仓库，
  每个框架最多读取 4 页，每页 50 个候选。Star/Fork/更新时间决定候选顺序，AI 判断插件、框架和安装信息。
- 每任务最多分析 200 个不同仓库，依赖递归最多 5 层。已有插件直接复用，不覆盖其配置。
  循环、缺失、无文档依据的依赖，以及数据库、系统软件等要求，记录为人工准备项。
- 仓库文档和模型输出仅作为不可信资料，不执行其中的命令。没有可用发布包、文档或受支持安装规则
  的条目保留人工处理要求，不伪造可安装配置。
- 时间预算从实际执行开始计算，覆盖 GitHub、AI 和等待；取消、超时或出错保留已提交的条目。
  单仓库失败可继续；GitHub 认证失效、明确限流或 AI provider 不可用结束本次任务。
- GitHub 429，或有额度耗尽／secondary rate limit 证据的 403，立即中断且不自动重试。
  任务详情显示安全原因、已完成结果和 GitHub 返回的恢复时间。普通权限 403 单独报告。
- 任务历史保留 7 天。应用重启后遗留的执行任务及启动前的排队任务标记失败，需管理员重新提交；
  重新提交时跳过已导入条目。
- 后续安装仍使用现有服务器队列。未核对配置需再次确认；人工准备项未清除或安装规则缺失时阻止
  自动安装。选择发布包和升级时重新检查真实压缩包，使用当前目录安装规则；修改配置会改变预检哈希。
  可移植目录导入／导出包含 AI 元数据和安装配置。

## 开发验证

完整质量基线：`uv run python scripts/check_baseline.py`。

独立浏览器回归：在 `frontend/` 运行
`npx playwright test --config=playwright.ai-import.config.ts`。
测试使用本地模拟后端 `127.0.0.1:38111` 和 Next 开发服务 `localhost:31801`，覆盖中英文、
390px／1440px 视口、提交、取消、全局 Token 验证和插件核对。不会调用真实 GitHub／AI，也不会
修改数据库或执行 SSH。需要本机 Chrome。

新增 Alembic revision 随面板下次正常启动自动迁移，遵循现有启动迁移机制。
